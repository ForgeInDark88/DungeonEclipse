# Бюджет размера

Потолок готовой сборки — около 1 ГБ. Это потолок, а не цель: вес
должен расти только от настоящего контента. Никаких пустых шумов,
дубликатов и несжатых копий.

Проверка: `python3 tools/size_report.py` (отчёт) и
`python3 tools/size_report.py --check` (падает при превышении; запускается
в CI после тестов).

| Категория | Потолок, МБ | Что входит |
|---|---|---|
| Текстуры и спрайты | 250 | `assets/**` .png/.webp/.svg/.webm, кроме фонов, тайлов и UI |
| Фоны и тайлсеты | 120 | `assets/sprites/backgrounds/`, `assets/sprites/tiles/` |
| UI и иконки | 40 | `assets/ui/`, иконки предметов, навыков, достижений, улучшений |
| Музыка | 330 | `assets/audio/music/` |
| Звуковые эффекты и амбиент | 120 | остальное `assets/audio/` |
| Шрифты | 15 | .ttf / .otf / .fnt / .woff |
| Данные, сцены, код | 30 | .tres / .tscn / .gd / .gdshader / локализация / настройки |
| Прочее | 20 | инструменты, тесты, документация, метаданные импорта |
| **Итого** | **925** | запас до 1 ГБ — 99 МБ |

Дополнительно:
- **Один файл — не больше 100 МБ.** Больше GitHub не примет даже через
  LFS-указатель.
- Категория определяется первым подходящим правилом в
  `tools/size_report.py` (`CATEGORIES`). Шрифты и музыка проверяются
  раньше общих правил.

## Как вес остаётся «честным»

- **Музыка** — OGG Vorbis q5 (~160 кбит/с стерео, около 1,2 МБ в
  минуту). Треки зациклены по точке петли, без тишины в хвосте.
- **SFX** — моно, 22–44 кГц, обрезаны по звучанию.
- **Пиксель-арт:**
  - PNG с палитрой, где получается;
  - спрайт-листы и атласы вместо россыпи мелких файлов;
  - импорт: фильтр Nearest, без mipmaps, Lossless; крупные фоны — VRAM
    Compressed.
- **Генераторы** (`tools/`) детерминированы. Повторный запуск даёт тот же
  файл, а не новую копию.

## Где лежат тяжёлые файлы: Git LFS

Правила лежат в `tools/lfs/gitattributes.lfs`. По ним в LFS идут:
- `*.ogg`, `*.wav`, `*.mp3`;
- шрифты `*.ttf`, `*.otf`;
- видео `*.webm`, `*.ogv`;
- фоны `assets/sprites/backgrounds/*.png`;
- любые `*_atlas.png` и `*_large.png`.

Мелкие спрайты и иконки остаются в обычном git. Так их видно в диффах и
не нужен лишний обмен с LFS.

**Почему LFS ещё не включён.** Облачная сессия, которая готовила этап B,
не может загружать объекты в GitHub LFS: её прокси отвечает 403 на
`lfs.github.com`. Если отправить коммит с указателями без самих объектов,
репозиторий сломается. Поэтому переход делается одной командой с машины
разработчика:

```
bash tools/lfs/enable_lfs.sh   # хуки LFS, правила в .gitattributes, перевод уже лежащих файлов
git push
```

История при этом не переписывается: старые версии файлов остаются в
обычном git. Сейчас весь репозиторий весит 55 МБ, файлов больше 100 МБ
нет, так что с переходом можно не спешить. Сделать его нужно до того,
как музыка этапа D (≈300 МБ) попадёт в репозиторий.

**Квота.** У бесплатного GitHub на LFS ограничены и место, и трафик. Каждый
CI-чекаут с `lfs: true` скачивает все LFS-файлы заново. Когда LFS будет
включён и вес вырастет, CI стоит кэшировать `.git/lfs` (actions/cache по
хэшу `git lfs ls-files -l`).

**Проверка.** `size_report.py --check` падает на PNG больше 1 МБ, если
он не попадает ни под одно правило LFS. Такой файл нужно переименовать в
`*_large.png` или `*_atlas.png`.

## Сборка

`tools/build.sh [Windows|Linux|Web]` экспортирует проект всеми
пресетами, для которых установлены шаблоны, и печатает вес сборки.
Ту же сводку выводит `python3 tools/size_report.py --build build`.
Проверка падает, если один файл сборки больше потолка 1 ГБ.
