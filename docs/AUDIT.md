# Аудит DungeonEclipse

Состояние на начало большого этапа «аудит и расширение». Источники: сама
папка проекта (сцены, скрипты, данные, ассеты), `git log` (318 коммитов),
прогон всех тестов, замеры. README местами устарел; где он расходится с
кодом, здесь записан код.

Godot 4.3, GDScript, рендер `gl_compatibility`. 235 скриптов, 34 сцены,
634 файла данных `.tres`. Размер без `.git` и `.godot` — 280 МБ, из них
ассеты ~57 МБ (музыка 40 МБ), остальное — локальные сборки в `build/`
(они в `.gitignore`). `.git` — 107 МБ, Git LFS не настроен.

**Графика:**
- Тайлсет без полного автотайлинга (47 краёв).
- Иконки 16×16, а цель — 32×32.
- Своего пиксельного шрифта нет: используется встроенный шрифт Godot (с кириллицей). Нужен свободный пиксельный шрифт → этап C, `docs/CREDITS.md`.

**Звук:**
- `AudioManager` уже умеет шины Music, SFX и UI, кроссфейд, лимит голосов, 2D-позиционирование и подводный фильтр.
- Нет отдельной шины Ambient (амбиент идёт через SFX), нет динамических слоёв музыки в бою и реверберации по типу локации → этап D.

**Техника:**
- **Пути к ассетам.** `asset_paths.gd` и `AssetPaths.tex()` с предупреждением вместо краша уже есть, но 12 мест в коде грузят `res://assets/...` напрямую через `load()`, а 5 — через `preload()`. При отсутствии файла `preload` ломает разбор скрипта → этап B.
- **Шум компиляции в старых тестах.** Восемь старых `-s`-тестов печатают «SCRIPT ERROR: Compile Error … Identifier not found: ItemDatabase». Они статически ссылаются на классы, которые используют автозагрузки, а при разборе `-s`-скрипта автозагрузок ещё нет. Тесты проходят, игра не затронута: импорт проекта и запуск игры чистые. Новые тесты в `tools/tests/` написаны без этого. `run_tests.sh` считает такие строки отдельно и не валит на них тест. Убрать полностью — перевести старые тесты на `load()` (низкий приоритет).
- **Нет Git LFS и бюджета размера** → этап B.
- **Нет CI** → добавлен (см. ниже).
- **Вес и память.** Фоны и музыка грузятся при входе в биом и не выгружаются явно. Пока это не проблема (ассеты 57 МБ), но станет ею при росте → этап B, загрузка по требованию.

**UX и доступность** (→ этап G):
- геймпад в меню проверен не везде;
- нет режима для дальтоников, субтитров звуков и отключения вспышек;
- отключение тряски — проверить.

## 5. Риски

1. **Рост объёма.** Чтобы дойти до ~1 ГБ «без воды», нужно прежде всего удлинить и умножить музыку (OGG q5 ≈ 1 МБ/мин). Цель — около 200–250 минут музыки, это 25+ треков по 2–4 минуты плюс слои. Графика при пиксель-арте весит мало: даже 500 иконок 32×32 и все атласы займут десятки мегабайт. Значит, итоговый вес законно получится заметно меньше 1 ГБ. Это нормально: 1 ГБ — потолок.
2. **Время тестов.** Полный набор идёт около 45 минут на 4 ядрах (1200 локаций, сеть). На push работает быстрый набор (~8 мин).
3. **Процедурный арт и звук.** Это заглушки высокого качества, но не авторская работа. Все имена файлов и размеры документированы, чтобы их можно было заменить.
4. **Кооп при каждом новом контенте.** Любой новый случайный бросок при генерации должен совпадать у хоста и гостя: см. исправление `floor_players` и отдельные ГСЧ у затопления и `_chests_within_reach`.

## 6. Приоритеты

1. Этап A (этот): аудит, критические баги, тесты, CI — **сделано**.
2. Этап B: бюджет и отчёт о размере, LFS, импорт, загрузка по требованию, проверка путей.
3. Этап E и C вместе: контент в `.tres` и арт под него (предметы, иконки 32×32, классы, расы, враги, боссы, события, лор, достижения, шаблоны комнат).
4. Этап D: длинная многослойная музыка, 300 SFX, шина Ambient, слои боя.
5. Этапы F и G: полировка систем, доступность, производительность, экраны.

## 7. Тесты

`tools/run_tests.sh` (быстро: `--quick`) запускает:
- импорт проекта;
- новые тесты в `tools/tests/`:

  | Тест | Что проверяет |
  |---|---|
  | `data_test` | загрузка всех `.tres`, уникальность id, наличие арта |
  | `level_gen_test` | 500 сидов этажей; выход и сундуки достижимы для героя, ничего в скале, затопленные ванны над полом |
  | `combat_sim` | время на убийство: классы × враги × этажи и стражи → `docs/BALANCE.md` |

- прежние тесты: сохранения, город, карта, события, реликвии, квесты, горячие клавиши, перенастройка, ИИ, поток игры, вода, живность, загрузка слоёв, 1200 локаций, кооп.

Полный прогон после исправлений A1–A5 — всё зелёное:
- импорт проекта;
- 23 набора проверок;
- 1200 локаций без ошибок;
- кооп-сценарии `world_layers`, `world_coop`, `world_flow`, `world_net` (23 проверки).

Цена исправления A1 — проверки сундуков в генераторе: этаж строится в
среднем 58 мс вместо 13, но обход запускается только тогда, когда
какой-то сундук стоит на мостке.
CI: `.github/workflows/tests.yml`, на каждый push.
